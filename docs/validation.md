# 验证记录与已知限制

2026-11-05，在一块 ESP32-S3（16 MB Flash、8 MB PSRAM）与一台真实 iPhone 上完成。固件版本 `0.2.2-hybrid2`。不公开设备标识、账号截图或订单内容。

## 已验证

- 新仓库使用无真实凭据的临时配置，ESP32 core 3.3.2 STA 独立构建成功：Flash 1,510,879 bytes（45%），全局内存 100,144 bytes（30%）。未把编译产物或临时配置上传。
- Flash 写入哈希验证通过，原固件完整备份保留在本地。
- 带 Token 的 LAN 状态读取成功；无 Token 返回 HTTP 401。
- 绝对点击设置图标、远处左上角返回按钮均命中。
- 498 × 1080 截图上从 `(250,855)` 拖到 `(250,420)` 成功滚动设置；从 `(250,1075)` 拖到 `(250,420)`，300 ms，成功返回桌面。
- `key cmd+space` 打开 Spotlight，`type 123` 显示数字，随后清除。
- UxPlay 持续截图下，进入京东“我的 → 待评价 → 问答 → 邀我回答”，打开回答框，切换简体拼音全键盘并输入中文。提交后出现“发布成功”。
- HID 描述符、参数拒绝、插值终点与按键报告通过 C++ ASan/UBSan 测试；JPEG 分片提取、缓存状态通过 Python 测试。
- 新仓库 4 项 Python 测试、C++ ASan/UBSan 测试、Python 编译检查、构建脚本语法检查与 Skill 格式检查通过。GitHub Actions 配置了无需硬件的源码检查。

## AirType 中文输入验收

- AirType 1.1，使用其局域网 HTTP `/pair`、`/status`、`/command` 接口；没有通过第三方云服务或跨设备剪贴板传输文字。
- 测试页成功插入中文、标点与 ASCII 混排文本，用户和实时画面均确认。
- 切到苹果备忘录后，读取新码配对，成功插入一段完整中文；第二次追加含换行文字也成功。
- 京东“邀我回答”打开真实回答框，读取当前码后一次写入完整中文，读图核对后点击发布，出现“发布成功”。
- 备忘录与京东单次插入 HTTP 响应约 27 ms 和 38 ms，仅为当次接口响应时间，不是端到端任务耗时或性能保证。
- 重开键盘可生成新码，旧 Token 不保证可复用。旧会话、断线后的处理必须核对画面，禁止自动重放不确定的插入。
- 配套 `tools/airtype.py` 使用本地 HTTP 模拟服务验证 UTF-8 原文、鉴权、Token 文件 0600 权限、配对拒绝及错误后不自动重试；全仓库 8 项 Python 测试通过。手机验收时采用同一协议，新增 CLI 没有为测试重复发布内容。
- Remoboard 对照测试在跨 App 场景出现已配对但未输入的现象，根因未确定，不作为默认后端。

## 2026-11-06：动作 API 实机验收

- 使用真实淘宝已购商品，完成一条中文五星评价，并读到发布成功页面；未为补奖励添加无关图片。
- `iphone_act` 已在真实板子上完成进入评价页、点星、打开键盘、发布及确认发布。进入评价页约 3.05 s，打开发布确认框约 2.43 s，确认发布并读到成功页面约 2.90 s。这些是单次接口耗时，包含控制、等待及 OCR，不是完整任务耗时或速度保证。
- 中文正文通过现有 AirType 客户端原文插入，HTTP 响应约 0.109 s；自动配对封装在本次实测中被小字地址 OCR 阻止，不能记作自动输入端到端通过。
- 已保存的私有键盘截图用于离线回放：加入仅在配对面板出现时触发的底部局部放大 OCR，读到了有效 `.local` 地址和配对码。键盘正常并列显示 IP 与 `.local` 地址，现优先选择同端口、相邻行中的唯一 IP；两个 IP 或不同端口仍视为歧义。数字不靠猜测修补。新识别逻辑通过真实截图回放，但整条自动输入链路仍待下一次实机验收。
- 首次冷启动局部 OCR 曾约 21.5 s；缓存与热启动不能代表首次调用速度。OCR 文本会有抖动，严格的页面一致性检查可能拒绝未变化页面，稳定等待也可能在动作已生效后返回 timeout。遇到此情况先读结果，不盲目重复动作；此项仍需优化。
- 本次也发生投屏会话中断和旧画面拒绝；恢复连接后继续。连续接收进程存活不等于镜像仍有效。

## 尚未解决或充分验证

- Consumer `homescreen` 指令返回 `ok`，测试手机未返回桌面；使用已验证的底部上滑手势。
- `hybrid1` 的键盘正常，但绝对点击失败；`hybrid2` 把绝对指针 collection 放在相对鼠标之前后成功。这只是本机兼容性证据，不是所有 iOS 的通用规则。
- 多机型、多 iOS 版本、横竖屏切换、边缘全范围、长时间稳定运行尚未系统验证。不要宣传为免校准的全机型方案。
- 原 App/BLE、板子 AirPlay、OTA、旧相对鼠标路径没有完整回归测试。保留源码不等于全部功能验收通过。
- AirType 已解决本次测试场景的整段中文输入；长时间、多机型、复杂 emoji 和超长文本仍待验证，部分输入框不允许第三方键盘。备用拼音仍有同音候选问题。固件本身没有 Unicode 直接输入能力。
- UxPlay 只负责画面，不负责鼠标纠偏。绝对坐标来自 HID 与截图映射。
- 持续截图减少重复启动开销，不消除模型推理、观察轮次、AirPlay 编解码或输入法耗时。尚无可复现的端到端速度基准。

## 解析后端实验结论

2026-11-06，在本项目使用的 Mac 与 iPhone 上试验了两条解析路径，当前保留 Apple Vision 文字 OCR＋OmniParser V2 图示定位的混合方案。纯 Apple OCR 开关仍可用于快速文字观察。

- 混合模式已在淘宝追评中完成发布，使用图示侦测给出的收起箭头坐标，并通过原图确认含义。
- EasyOCR 中文识别可以运行，但在本次淘宝页面上存在中文字、小字与 AirType 底部网址误识别；单张页面约 1.6～5 秒，结合影格更新间隔，多次触发过期保护、布局核对拒绝和等待超时。试验未完成新的追评发布。
- OmniParser 图示描述模型在一个返回箭头裁剪样本上输出了“向下箭头”，语义并不可靠。逐个描述某张主画面的图示耗时约 31 秒，使结果失去实时操作价值。

这些是有限样本的本机观察，不是统一数据集上的准确率排名。描述误判与图示定位误差是不同问题：当前混合模式不运行描述模型，仍可能漏检、重复框选或框选整列商品；需要原图确认与动作后结果验证。

已移除完整模式的运行入口、工作程序和为该试验延长的探测等待，未放宽过期画面保护。下载的模型与临时产物保留在忽略的本机 runtime 目录，未纳入仓库；当前运行服务恢复混合模式。后续如重新评估，应先做固定截图离线对照再接入实际任务。
